# satysfi-formatter 仕様書

> 実装の進め方・テストの進め方は [implementation.md](./implementation.md) に分けてある。本書は「何を出力するか」だけを定める。
> 例の出力は、特に断りがなければ インデント幅 4・行幅 80 の場合のもの。

## 1. 概要

`satysfi-formatter` は SATySFi (`.saty` / `.satyh`) のソースコードを整形するツールである。
パーサーには、monaqa さんの [satysfi-parser](https://github.com/monaqa/satysfi-parser) をベースに、コメントや空行を CST から取り出せるようにするなどの拡張を加えたフォーク ([usagrada/satysfi-parser](https://github.com/usagrada/satysfi-parser)) を使う。このパーサーが生成する CST (具象構文木) を入力とし、整形済みの文字列を出力する。

- コマンド名: `satysfi-fmt`
- ライブラリ: `satysfi_formatter` crate (`format` / `formatting` を公開)
- 対象: 上のパーサーの `grammar::program` でパースできる SATySFi コード

### 1.1 満たすべき性質

1. **構文を変えない**: 整形の前後で、空白とリスト・レコード末尾の `;` を除いたトークン列が変わらない。
2. **冪等**: 整形結果を再度整形しても同じ結果になる。
3. **コメントを失わない**: すべてのコメントが出力に残る。
4. **行幅を意識する**: リスト・レコード・関数適用などは、行幅に収まれば 1 行、収まらなければ縦に展開する。
5. **利用者が制御できる**: コメントの directive で、整形しない範囲を指定できる。

### 1.2 非目標

- 構文エラーのあるコードの整形 (§12)
- 行幅の厳守 (行幅は目安で、長い識別子や文字列は超えることがある。全角文字は 2 桁として数える)
- 識別子の変更など、意味に関わる変換
- テキスト (水平モードの文章) の行幅に合わせた折り返し (§9.3)

## 2. インターフェース

### 2.1 CLI

language server やエディタも、このコマンドをプロセスとして呼んで使えるように、引数・標準入出力・終了コードを公開インターフェースとして定める。

```bash
satysfi-fmt [OPTIONS] [FILE]...
```

| オプション | 説明 |
|---|---|
| `-w`, `--write` | 入力ファイルを整形結果で上書きする。内容が変わらないファイルは書き直さない |
| `-o`, `--output <PATH>` | 整形結果をこのファイルに書く |
| `--check` | 何も出力せず、整形されていないファイル名を `<ファイル名>: not formatted` として標準エラーに出す |
| `--config <PATH>` | 設定ファイルを指定する。省略すると §2.4 のとおり探す |
| `--assume-filename <PATH>` (別名 `--stdin-filepath`) | 標準入力を整形するときの仮のファイル名。設定ファイルの探索とエラー表示に使う |

- 整形の設定 (行幅・インデント幅など) は **設定ファイルだけ** で行い、コマンドライン引数では変えない。
- `FILE` を省略するか `-` を指定すると、標準入力を読む。
- 出力先:
  1. `-o` があれば、そのファイルに書く。
  2. `-w` があれば、入力ファイルを上書きする。
  3. どちらもなければ標準出力に整形結果だけを出す。エラーなどは標準エラーに出す。
- `-w` / `--check` / `-o` は、`-w` と `--check`、`-w` と `-o`、`--check` と `-o` のどの組も同時に指定できない。
- 複数のファイルは `--write` か `--check` のときだけ指定できる。標準入力に `--write` は使えない。
- 複数のファイルを渡したとき、途中でエラーになっても残りは処理する。

終了コード:

| コード | 意味 |
|---|---|
| 0 | 成功 (`--check` のときは、すべて整形済み) |
| 1 | `--check` で、整形されていないファイルがあった |
| 2 | エラー (構文エラー、読み書きの失敗、設定ファイルの誤り、引数の誤り) |

### 2.2 設定

| 項目 | 型 | 既定値 | 説明 |
|---|---|---|---|
| `line_width` | 1 以上の整数 | 80 | 行幅 |
| `indent_width` | 1 以上の整数 | 4 | インデント幅。`use_tabs` のときは、タブ 1 つをこの桁数として行幅を数える |
| `use_tabs` | bool | false | インデントにタブを使う |
| `final_newline` | bool | true | 出力の末尾に改行を 1 つ付ける |
| `block_command_space` | bool | false | ブロックコマンドのテキスト引数の前に空白を入れる (§9.1) |

### 2.3 ライブラリ API

「設定を解決する関数」と「文字列を整形する純粋な関数」に分ける。ファイルの入出力や LSP の型の扱いはライブラリの外 (呼び出し側) で行う。

| 項目 | 説明 |
|---|---|
| `format(input: &str, config: &FormatConfig) -> Result<String, FormatError>` | 整形する。入出力は行わない。構文エラーは `FormatError::Parse { line, column, expected }` (0 始まり) になる |
| `FormatConfig` | 整形の設定 (§2.2)。`Default` は既定値 |
| `PartialConfig` | 一部だけ指定された設定。`or(lower)` で重ね、`build()` で既定値を埋める |
| `PartialConfig::from_editor_options(tab_size, insert_spaces, insert_final_newline)` | エディタ (LSP の `FormattingOptions`) の指定から設定を作る。`tab_size` が 0 なら `indent_width` を指定しない。`insert_spaces` が false なら `use_tabs` |
| `resolve_config(path: &Path) -> Result<PartialConfig, ConfigError>` | `path` に対応する設定ファイルを探して読む。見つからなければ空の設定。呼ぶたびに読み直す |
| `formatting(input, FormattingOptions) -> Vec<TextEdit>` | 旧 API。satysfi-language-server が移行するまでの互換として、feature `lsp` (既定で有効) の下に残す。非推奨。ファイル全体を置き換える `TextEdit` を 1 件返す。構文エラーのときは空の `Vec`。`FormattingOptions` の `lineWidth` プロパティ (正の数) があれば `line_width` として使う。設定ファイルは読まない |

language server がライブラリを直接使うときは、設定を **設定ファイル → エディタの指定 → 既定値** の順に重ねる。プロセスとして呼ぶときは §2.1 の標準入力を使う。

### 2.4 設定ファイル `.satysfi-fmt.toml`

```toml
line_width = 100
indent_width = 2
use_tabs = false
final_newline = true
block_command_space = false
```

- 整形するファイルのディレクトリから親へ向かって探し、最初に見つかったものを使う。相対パスでも、カレントディレクトリより上まで探す。
- 標準入力で `--assume-filename` がないときは、カレントディレクトリから探す。
- `--config` を指定したときは、探さずにそのファイルを使う。
- 書かない項目は既定値になる。
- 未知のキーと、`line_width` / `indent_width` が 0 のものはエラー。

## 3. ファイル全体の構成

次のブロックを **空行 1 つ** で区切って並べる。存在しないブロックは出力しない。

```
@stage: ...        ステージ
@require: / @import:  ヘッダ
let ... など       前処理部 (preamble)
document ...       本体
```

- **ステージ**: `@stage: <値>` の形にする。
- **ヘッダ**: `@require: pkg` / `@import: pkg` を 1 行 1 件、元の順序で並べる。コロンの後のスペースは 1 つにする。ヘッダ同士の間の空行は取り除く。
- **前処理部**: 文 (§6) を並べる。`.saty` ファイルでは末尾に `in` の行を置く (`.satyh` では置かない)。
- **本体**: 式。`document(||)'<...>` のように、各部分の間にスペースを置かない。

```satysfi
@require: stdjareport

let x = 1
in

document(||)'<>
```

## 4. 共通の規則

### 4.1 インデントと改行

- インデントはネストごとに `indent_width` 個のスペース 1 段分。`use_tabs` のときはタブ 1 つを 1 段分とし、行幅の計算ではタブ 1 つを `indent_width` 桁として数える。
- `% satysfi-fmt off` の範囲 (§11) は、`use_tabs` のときも元の空白のまま。
- 行末の空白は除去する。
- ファイルの末尾の空行は取り除き、`final_newline` が有効なら改行 1 つで終える。
- 入力の連続する空行は 1 行に畳む。空行を保持する場所は、文の並び (§6.1)・垂直モードのブロックの並び (§9.1) に限る。それ以外の場所の空行は取り除く。
- 単独行のコメントと次の文/ブロックの間、およびコメント同士の間の空行は、その位置に残す (最大 1 行)。

### 4.2 行幅による折り畳み

「収まれば 1 行、収まらなければ縦に展開する」という規則を、以下の構成要素に適用する。展開は外側から順に行い、内側が収まればその部分は 1 行のまま残す。

- リスト・レコード・タプル (§5.3)
- 関数適用の引数 (§5.4)
- 演算子の連鎖 (§5.5)
- `if` / `match` / `fun` の本体 (§5.6)
- `let` の右辺 (§6.2)
- 型の矢印 (§7)

一方、次のものは行幅に収まらなくても折り返さない。

- 文字列リテラル、インラインコード (§5.8)
- 水平モードのテキストの 1 行 (§9.3)
- 数式の中身 (§9.4)
- `% satysfi-fmt off` から `on` までの範囲 (§11)

## 5. 式

### 5.1 括弧で始まる右辺

`=` / `->` / `<-` の右辺が、括弧で自分自身を折り返せる式 (リスト・レコード・タプル・ブロック/インラインテキスト・数式・括弧で終わる関数適用) のときは、右辺を同じ行から始める。それ以外の式は、収まらなければ演算子の後で改行し、右辺を 1 段深く字下げする。

```satysfi
let y = vconcat [
    aaaaaaaa;
    bbbbbbbb;
]
let z =
    aaaaaaaa
        |> bbbbbbbb
```

右辺の前に単独行のコメントがある場合は、括弧で始まる式であっても `=` / `->` の後で改行し、コメントを右辺と同じ字下げの単独行に置く。

```satysfi
let g x =
    % note
    (a, b)
```

### 5.2 括弧・演算子・定数

- 二項演算子の前後にスペースを 1 つ置く。`(+)` のように括弧で囲んだ演算子はそのまま。
- 単項演算子: `-x` は間にスペースを置かない。`not x` は置く。前置演算子 `!x` / `&y` は置かない。
- フィールドアクセスは `r#field#other`。モジュール付きの式は `M.(f 1)`。
- 括弧のない `Some 1` と括弧つきの `Some(1)` は、元の書き方を保つ。
- 単位定数は `()`。長さは `1.5pt` のようにそのまま。

### 5.3 リスト・レコード・タプル

| 状態 | リスト | レコード |
|---|---|---|
| 要素なし | `[]` | `(||)` |
| 1 行に収まる | `[1; 2; 3]` | `(|a = 1; b = 2|)` |
| 収まらない | 縦に展開 | 縦に展開 |

- 1 行のときは末尾の `;` を付けず、レコードは `(|` `|)` の内側にスペースを置かない。
- 縦に展開するときは、開き括弧の後で改行し、要素を 1 行ずつ 1 段深く字下げして並べ、**最後の要素にも `;` を付ける**。閉じ括弧は開き括弧のある行と同じ字下げ。
- レコードの更新は `(|r with a = 1|)`。
- タプルは `(1, 2, 3)`。縦に展開するときは `,` 区切りで、最後の要素に `,` を付けない。

```satysfi
let x = [
    aaaaaaaa;
    bbbbbbbb;
]
let t = (
    aaaaaaaa,
    bbbbbbbb
)
```

### 5.4 関数適用

`f a b c`。

- 収まれば 1 行。
- 収まらなければ、関数名の次の行から 1 引数ずつ改行し、1 段深く字下げする。
- 引数が括弧で自分自身を折り返せる式 (リスト・レコード・ブロックなど) のときは、直前と同じ行に置き、括弧の中身を縦に展開する。
- 括弧で包まれた式が引数のとき、収まらなければ括弧の中でも引数ごとに改行する。
- オプション引数は `?:x`、省略は `?*` と書く。

```satysfi
let y =
    f
        aaaaaaaa
        bbbbbbbb
let z = vconcat [
    aaaaaaaa;
    bbbbbbbb;
]
let w =
    foo
        (aaaaaaaaaaaaaaaa
            bbbbbbbbbbbbbbbb)
        (cccccccccccccccc
            dddddddddddddddd)
```

### 5.5 演算子の連鎖

`a |> b |> c`、`a + b + c` など。

- 収まれば 1 行。
- 収まらなければ、**演算子を行頭**に置いて 1 項ずつ改行する。2 項目以降は 1 段深く字下げする。

```satysfi
let y =
    aaaaaaaa
        |> bbbbbbbb
        |> cccccccc
```

### 5.6 制御構文・ラムダ

**`if`**: 収まれば 1 行 (`if a then b else c`)。収まらなければ、`then` / `else` の本体を別の行に置いて 1 段深く字下げする。`else if` は連鎖として扱う。

```satysfi
let g =
    if a then
        b
    else if c then
        d
    else
        e
```

**`match`**: 常に腕を 1 行ずつ並べる。腕の `|` は `match` と同じ字下げ。本体が収まらなければ `->` の後で改行する。ガードは `| B y when y > 0 -> 2`。

```satysfi
let g =
    match x with
    | A -> 1
    | B y when y > 0 -> 2
    | _ -> 3
```

**`while`**: `while c do body`。
**`fun`**: `fun x y -> body`。収まらなければ `->` の後で改行し、本体を 1 段深く字下げする。括弧で囲まれた `fun` は括弧の中で折り返す。
**代入**: `a <- b`。
**逐次実行**: `a before b`。収まらなければ `before` を行末に置いて改行し、各式を同じ字下げに並べる。

### 5.7 `let ... in`

式の中の `let ... in` は、常に `in` の後で改行し、本体を同じ字下げで次の行に置く。1 行に書かれていても展開する。`open Foo in`、`let-mutable`、`let-rec` の束縛も同様。`in` の前後のコメントは、元の側に残す (§10.2)。

```satysfi
let x =
    let y = 1 in
    let z = 2 in
    y + z
```

### 5.8 文字列・パス

- 文字列リテラルは行幅に収まらなくても分割しない。収まらない場合は直前の `=` の後で改行する。
- 改行を含む文字列リテラルの内側は、元のまま出力する (字下げを変えない)。
- パス式 `<[ ... ]>` は §5.9 を参照。

### 5.9 パス式

`<[ 始点 セグメント ... ]>`。始点は式 (多くは `(x, y)` のタプル)。セグメントは次の 4 種類。

| セグメント | 出力 |
|---|---|
| 直線 | `-- 点` |
| 曲線 | `.. controls 点1 and 点2 .. 点3` |
| 直線で閉じる | `-- cycle` |
| 曲線で閉じる | `.. controls 点1 and 点2 .. cycle` |

- 記号と点の間、セグメントの中の語の間はスペース 1 つ。入力の空白や改行は引き継がない。
- 全体が行幅に収まれば 1 行で、`<[` の後と `]>` の前にスペース 1 つを置く。
- 収まらなければ、`<[` の後で改行し、始点とセグメントを **1 つずつ 1 行** に、1 段深く字下げして並べる。`]>` は `<[` と同じ字下げの行に置く。セグメントの中の点のタプルは、セグメントが行幅を超えたときにタプルの規則 (§5.3) で 1 要素ずつ折り返す (パス専用の例外はない)。
- パス式は括弧で自分自身を折り返す式として扱わないので、`let` の右辺が収まらないときは、`=` の後で改行してから `<[` を始める (§5.1)。
- パス式を関数の最後の引数にしたときは、リストやレコードのように直前の行に密着させず、収まらなければ全引数を 1 行ずつ縦に並べる (§5.4)。

```satysfi
let p = <[ (0pt, 0pt) -- (1pt, 1pt) -- cycle ]>

let q =
    <[
        (0pt, 0pt)
        -- (1pt, 1pt)
        .. controls (1pt, 0pt) and (0pt, 1pt) .. (2pt, 2pt)
        -- cycle
    ]>
```

コメント:

- パス式の中にコメントがあれば、必ず縦に展開する。
- `-- cycle` の `--` と `cycle` の間にあるコメントは、`-- cycle` の前の行に移す。
- 最後のセグメントの後ろにあるコメントは、`]>` の前の行に、セグメントと同じ字下げで置く。

```satysfi
let p =
    <[
        (0pt, 0pt)
        % c
        -- cycle
    ]>
```

## 6. 文

### 6.1 文の並び

前処理部・`struct` の中の文は、1 行 1 文で並べる。

- 元の文の間の空行は最大 1 行まで残す。
- `module` 文の前後には、元の空行の有無に関わらず空行を 1 行置く。

### 6.2 `let`

```satysfi
let name arg1 arg2 = value
let f : int -> int | x = x
```

- `let` / パターン / 引数 / `=` の間はスペース 1 つ。右辺は §5.1 に従う。
- 引数が多く、ヘッダ (`=` まで) が行幅に収まらないときは、入るだけ詰めて改行する。続きの行は、本体より 1 段深く字下げする (引数のパターンは分割しない)。`=` は最後の引数と同じ行に置き、本体は次の行に置く。

  ```satysfi
  let arrow-scheme strokef color lenL ((x1, y1) as pt1)
          ((x2, y2) as pt2) =
      Geom.atan2-point pt2 pt1
  ```
- `let-rec` は `and` で繋ぐ定義を新しい行に、元の字下げと関わらず `let-rec` と同じ位置で書く。`| pat = body` の腕は、1 段深く字下げして 1 行ずつ並べる。
- `let-inline` / `let-block` / `let-math` / `let-mutable`:

  ```satysfi
  let-inline ctx \foo x y = { #x; #y; }
  let-block ctx +bar x = '<
      +p { #x; }
  >
  let-math \sq x = ${\sqrt{#x}}
  let-mutable m <- 0
  ```
  コマンド名・引数が長いときは、`let` と同様に詰めて 2 段深く字下げする。

### 6.3 `type`

- バリアントが収まれば 1 行: `type t = A | B of int | C of int * string`。
- 収まらなければ、`=` の後で改行し、各バリアントを `| ` で始めて 1 行ずつ並べる。
- 型パラメータは `type 'a t = ...`。
- `and` で繋ぐ型は新しい行に `and` から書く。
- `constraint` は新しい行に 1 段深く字下げして書く。

  ```satysfi
  type 'a t = A
      constraint 'a :: (|x: int|)
  ```

### 6.4 `module` と `sig`

```satysfi
module M : sig
    type t
    val f : t -> u
    val +p : [inline-text] block-cmd
    direct \x : [int] inline-cmd
end = struct
    let f x = x

    module N = struct
        let h = 1
    end

    let i = 2
end
```

- 中身が空のときは `struct end` / `sig end` と書く。
- 中身は 1 段深く字下げし、`end` は `module` と同じ字下げ。
- `struct` の中は §6.1 の規則 (空行・`module` の前後の空行)。
- `open Foo` は 1 文として並べる。

## 7. 型

- 矢印型 `a -> b ?-> c`。収まらなければ、各矢印の後で改行し、2 項目以降を 1 段深く字下げする。括弧のない形のまま。
- 括弧つきの型は保つ: `(int -> int) -> int`。
- 直積 `int * string`、型適用 `'a list` / `Foo.t`、コマンド型 `[int?; string] inline-cmd`。
- レコード型は `(|a: int; b: string|)`。(`:` の前にスペースを置かず、後ろに置く。)
- 引数のないコマンド型は `[] block-cmd`。

## 8. パターン

元の書き方を保つ。

```satysfi
let f (a, b) [c; d] = a
let g (x :: xs) (Some y as z) (+) _ = 0
```

- タプルは `(a, b)`、リストは `[c; d]`、cons は `x :: xs`、`as` は `pat as name`。
- コンストラクタの括弧の有無 (`Some(x)` / `Some x`) は元のまま。
- 引数の位置のパターンは、長いヘッダでも分割しない (§6.2)。

## 9. テキスト

### 9.1 垂直モード `'<...>`

- 空のとき `'<>`。
- 中身があれば `'<` の後で改行し、ブロックを 1 行 (または 1 かたまり) ずつ 1 段深く字下げして並べる。`>` は `'<` と同じ字下げ。
- ブロック同士の間の空行は最大 1 行まで残す。
- ブロックは `+p{ ... }` / `+newpage;` / `#blk;` など。コマンド名と引数、引数同士の間にはスペースを置かない (`+p{ a }`、`+cmd(1)[2]{ x }`)。`block_command_space` が true のときだけ、テキスト引数 `{...}` / `<...>` の前にスペース 1 つを置く (`+p { a }`、`+cmd(1)[2] { x }`)。
- 1 つ目の引数は、コマンド名と同じ行に置く (間で改行しない)。
- 引数が長いときは、2 つ目以降の引数を 1 つずつ改行して 1 段深く字下げする。ただし前の引数が複数行になるときは、次の引数がその最後の行に収まる限り、改行せずに続ける (`...)(arg);`)。最後のテキスト引数 `{...}` は直前の行に続ける。

```satysfi
document(||)'<
    +p{ a }

    +section{ Sec }<
        +p{ b }
    >
    +very-long-command-name(aaaaaaaaaaaaaaaa)
        (bbbbbbbbbbbbbbbb){ text }
>
```

### 9.2 水平モード `{...}`

- 空のとき `{}`。
- 中身は前後にスペース 1 つを置いて `{ a b }` と書く。
- 連続する空白は 1 つにし、前後の空白は取り除く。
- インラインコマンドは `\emph{ x }` と、コマンド名と引数の間、引数同士の間にスペースを置かない (`\cmd(1)[2]{ x }{ y }`)。直後の括弧・文字との間は元の隣接関係を保つ。
- コマンドとテキスト引数の間にコメントがあるときは、元の改行を保つ。
- 隣り合うコマンドは、間に空白を入れない (`\emph{ b }\emph{ c }`)。
- 文章以外 (インラインコマンド・数式・埋め込みなど) を含む `{...}` が 1 行に収まらないときは、`{` の後と `}` の前で改行し、中身を 1 段深く字下げする。
- 埋め込みは `#inl;` / `#M.y;`。インライン数式は `${...}`。
- エスケープ (`\%` `\\` `\{` など)・インラインコード (`` `code` ``) はそのまま。

### 9.3 テキストの行

テキストの行は、行幅に収まらなくても折り返さない。入力に改行が含まれる場合は、その改行を保って縦に展開する。

```satysfi
+p {
    a
    b
    c
}
```

- 縦に展開する場合、`{` の後で改行し、各行を 1 段深く字下げし、`}` を `{` を含む行の字下げに揃える。
- コマンドの引数に複数行のテキストがあるときも同様に、その引数を縦に展開する。
- テキスト中の空行は取り除く。
- リスト項目 `* a` / `** b` は、1 項目 1 行に縦に展開する (字下げの深さは変えず、`*` の個数だけで表す)。
- 水平リスト `{| a | b | c |}` は 1 行に収める: `{ | a | b | c | }`。

### 9.4 数式 `${...}`

- 中身は元のままにし、空白を調整しない (`${a+b}`、`${\frac{a}{b} \sqrt{x}}`)。
- 数式の中身に改行があるときは、`${` の後で改行して各行を 1 段深く字下げし、`}` を揃える。
- 上付き・下付き (`a^2`, `b_i`, `d^{x y}_{z w}`)、プライム `a'^2`、`${| a | b |}` の数式リスト、`#x` の埋め込みはそのまま。
- コマンドの引数は種類に関わらずそのまま書く。数式中のコマンド引数にテキスト/ブロック/式が現れるときは、`\f!{ t }!<...>!(1)![1; 2]!(|a = 1|)` のように各引数を整形する。

## 10. コメント

### 10.1 保存と書式

すべてのコメントを出力に残す。コメントの書式は、`%` の後ろが空白・`%`・空文字でなければ、スペース 1 つを補う (`%c` → `% c`)。それ以外は変更しない。行末の空白は取り除く。

### 10.2 位置

| 分類 | 定義 | 出力位置 |
|---|---|---|
| 行末コメント | 同じ行の左にコードがある | 左の要素と同じ行に、スペース 1 つ空けて置く |
| 単独行コメント | 行にコメントのみ | 直後の要素の前に、その要素と同じ字下げで 1 行を占めて置く。後ろに要素がなければ、最後の要素の後に置く |

行コメントは行末まで続くので、後ろに続く記号 (`;`, `)`, `in` など) を飲み込まないように、次のように移す。

- 後ろに閉じ括弧や区切りが続く場所にある行末コメントは、**次の要素の前の単独行コメント**になる。
  - 例: `let y = % c\n  2` → `let y =\n    % c\n    2`
  - 例: `(1, % first\n 2)` → `(\n    1,\n    % first\n    2\n)`
- 演算子の前のコメントは、演算子の行の前に単独行で置く。
- 関数適用の引数の間のコメントは、次の引数の前に単独行で置く。
- `in` の前後のコメントは、元の側に残す。`in` の前の行末コメントは直前の要素の行末に、単独行コメントは `in` の前の行に、`in` の後の行末コメントは `in` と同じ行に、単独行コメントは `in` の後に置く。

```satysfi
let x = 1 % c
% own line before in
in % after in

% own line after in
document(||)'<>
```

### 10.3 リスト・レコード・文

- 要素と同じ行の行末コメントは、`;` の後ろに付けて残す (`1; % one`)。
- リスト・レコードの中にコメントがあれば、必ず縦に展開する。
- 要素のないリストにコメントだけがあるときは、`[` の後で改行してコメントを置き、`]` を次の行に置く。
- 文の並び・`match` の腕・型のバリアントの行末コメントは、その行に残す。

```satysfi
let x = [
    1; % one
    % own line
    2;
    % dangling
]
```

### 10.4 文の後ろの単独行コメント

文の並び (前処理部・`struct` の中) で、文の後ろにある単独行のコメントは、字下げと空行で「直前の文の本体の続き」か「次の文の見出し」かを決める。

```satysfi
let f x =
  % head
  x % tail
  % end
let y = 1
```

↓

```satysfi
let f x =
    % head
    x % tail
    % end
let y = 1
```

- 次の条件をすべて満たすコメントは、直前の文の本体の続きとして、本体と同じ字下げ (文の字下げ + 1 段) で出力する。
  1. 直前の文の先頭より深く字下げされている。
  2. 直前の文との間にも、前のコメントとの間にも空行がない。
- 文の直後から連続して条件を満たすコメントだけが対象で、条件を外れたコメント以降は、次の文の見出しになる。
- 文と同じかそれより浅い字下げのコメント、または空行で区切られたコメントは、次の文の見出しとして、文と同じ字下げで出力する。
- `% satysfi-fmt off` / `on` は、字下げが深くても常に次の文に付く。
- 区別できないときは直前の文を優先する。字下げが文より深ければ、見出しのつもりで書いていても本体の続きになる (`let a = 1\n   % x\nlet b = 2` の `% x` は 4 桁になる)。字下げがコメントの帰属を示す唯一の手がかりで、文より深く書くのは、その文に付ける意図であることが多いため。
- `struct` の末尾 (`end` の前) も同じ規則に従う。最後の文より深ければその文の本体の続きで、同じ字下げなら `struct` の中の最後のコメントになる。
- 本体の続きのコメントの後ろの空行は 1 行だけ残す。
- この規則は文の並びだけに適用する。垂直モードのブロックの並び (`+p{...}`) などには適用しない。

### 10.5 ファイルの構成まわり

- ヘッダ行のコメントは、そのヘッダの行に残すか、直前/直後に独立した行として置く。
- 本体の後ろのコメントは、本体との間に空行を 1 行置いて出力する。
- ファイル末尾に改行のないコメントも、改行を付けて出力する。

## 11. 整形の制御 (directive)

コメントで整形しない範囲を指定できる (clang-format の `// clang-format off` / `on` と同じ考え方)。

| コメント | 意味 |
|---|---|
| `% satysfi-fmt off` | ここから整形しない |
| `% satysfi-fmt on` | ここから整形を再開する |

```satysfi
let x = [1;   2]
% satysfi-fmt off
let table = [
  [1;   0;   0];
  [0;   1;   0];
]
% satysfi-fmt on
let y = [1;   2]
```

↓

```satysfi
let x = [1; 2]
% satysfi-fmt off
let table = [
  [1;   0;   0];
  [0;   1;   0];
]
% satysfi-fmt on
let y = [1; 2]
```

### 11.1 範囲

- `off` のコメントの次から `on` のコメントの手前までが対象で、**書いたとおりのまま** 出力される。空白・改行・空行・字下げ・間にあるコメントも変わらず、行幅を超えても折り返さない。
- `off` / `on` のコメント自体は対象に含まれず、通常どおり字下げが整えられる。
- 範囲の外は、通常どおり整形される。
- `on` がなければ、ファイルの最後まで整形しない。`module ... struct ... end` の中に `off` を書いても、`end` の後ろを含めて最後までである。
- `off` と `on` の組は何か所でも書ける。範囲の中に書いた `off` と、対応する `off` のない `on` は何も起こらない。
- コードの行末に書いたときは、その行の次から効く。
  - 行末の `off`: その行のコードは整形され、次の行から整形されない。
  - 行末の `on`: その行のコードは元のままで、次の行から整形に戻る。
- リスト・レコードの要素の間、垂直モード・水平モードの途中 (`+p` の並び、テキストの中) にも書ける。この場合、`off` / `on` のコメントだけが字下げされ、間の要素は元のまま。

```satysfi
let a = 1 % satysfi-fmt off
let   b  =  2
let   c  =  3 % satysfi-fmt on
let d = 4
```

### 11.2 指示として認識されるコメント

- `satysfi-fmt` と `off` / `on` の間には空白が 1 つ以上要る。`%` の後ろの空白はなくてもよい。`%` を重ねてもよい (`%% satysfi-fmt off`)。
- `off` / `on` の後ろに `:` を付けて理由を書いてよい (`% satysfi-fmt off: 表を揃えるため`)。
- 次のものは普通のコメントで、整形は止まらない。
  - `% off`
  - `% satysfi-fmt: off` (`satysfi-fmt` の直後にコロンを付けた書き方)
  - `% satysfi-fmt off the table` (`:` なしで文章が続くもの)
  - コメントの途中に書いたもの (`% 説明 satysfi-fmt off`)
  - 文字列の中に書いたもの
- `% satysfi-fmt skip` は廃止された。普通のコメントとして扱う。

### 11.3 構文の途中に書いた場合

構文の途中 (`let-rec` と関数名の間など) に書くと、整形でコメントの位置が変わり、範囲を正確には戻せないことがある。その場合、`off` / `on` の位置は変えないまま、整形しない範囲を広げる。

1. `off` と `on` を含む同じ階層のノードの並び (文の並びなら、`off` を含む文から `on` を含む文まで) を丸ごと元のまま出力する。
2. それでも `off` / `on` が元の位置に残らなければ、1 つ上の階層へ広げる。
3. 最後はファイル全体を元のまま返す。

整形がエラーになることはない。行頭や行末に書く通常の使い方では、範囲は広がらない。

### 11.4 注意

- 整形しない範囲の中も、SATySFi の構文として正しい必要がある。構文エラーは範囲の中でもエラーになる。
- `use_tabs` のときも、範囲の中の空白は変換しない。
- 整形の対象から外すファイルやディレクトリを設定する機能はない。

## 12. エラー処理

- 構文エラーのとき、`format` は `Err(FormatError::Parse { .. })` を返す。入力をそのまま返すことはしない。空の入力も構文エラーになる。
- CLI は構文エラーのとき何も出力せず、`<パス>:<行>:<列>: error: syntax error` を標準エラーに出す (行・列は 1 始まりで、列は文字数)。標準入力のときの `<パス>` は `--assume-filename`、省略時は `<stdin>`。終了コードは 2。出力ファイルや入力ファイルは書き換えない。
- 設定ファイルの誤り、ファイルの読み書きの失敗、引数の誤りも終了コード 2。
- 旧 API `formatting` は構文エラーのとき空の編集リストを返す。
